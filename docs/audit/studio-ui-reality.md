# Phase 16 — Studio UI Reality Classification

This document audits the Phase 15 web application (`packages/studio-ui`) against live production requirements.

---

## UI Panel Classification Matrix

| Panel / Component | Functionality | Reality | Underlying Data Source | Production Gap | Remediation |
| :--- | :--- | :---: | :--- | :--- | :--- |
| **Header Stepper** | Pipeline progress stages (Story -> Director -> Assets -> Routing -> Timeline -> QA -> Master) | **STATIC / DEMO** | Hardcoded HTML `.step-chip.completed` classes | Does not poll a live pipeline daemon or CheckpointManager. | Add `ExecutionModeBadge` (`MOCK`, `LOCAL`, `PRODUCTION`) and make stepper read from current checkpoint stage. |
| **Financial Savings Pill** | Displays `⚡ SAVED 75.4% ($2.50)` | **DEMO / DERIVED** | Hardcoded initial string; recalculates dynamically if user clicks shot cards. | Calculation is accurate for 2 sample shots, but labeled as static headline before pipeline run. | Explicitly label as `LOCAL DEMO METRICS` or bind to `production_summary.json`. |
| **Dual-Mode Player Viewport** | HyperFrames 2.5D parallax vs Video Compositor | **PARTIAL** | CSS transforms on DOM layers simulating camera push-in and lateral parallax; synchronized with JS `requestAnimationFrame` timeline scrubhead. | Renders live CSS animation, but not real encoded MP4 video stream. | Add actual HTML5 `<video>` player element when in Master Video mode. |
| **Multi-Track Timeline Lanes** | Visual lanes V1, A1, A2, A3, S1 with draggable playhead | **LIVE / CLIENT** | Real interactive DOM scrubber with 100px/s mapping, step frame, and timecode display. | Works smoothly in client, but displays hardcoded sample shots until loaded with real `timelineSequence`. | Support loading actual `TimelineSequence` JSON via file drop or project selector. |
| **Web Audio Stem Mixer** | Sliders for A1, A2, A3 and CC toggle | **PARTIAL** | Sliders update JS state values, and toggle hides/shows subtitle overlay. | Web Audio graph is scripted declaratively, but not hooked to local Web Audio Oscillator/MediaElement sources. | Hook HTML5 audio elements to master gain nodes. |
| **Screenplay Source Viewer** | Screenplay with character highlights and narrative beats | **LIVE / STATIC** | Hardcoded sample scene text with CSS `<mark>` character highlights and beat cards. | Clean presentation, but not connected to dynamic project selector. | Connect project dropdown to load corresponding story documents. |
| **Director Shot Cards** | Shot cards with camera pills and route badges | **LIVE / INTERACTIVE** | Clicking card toggles between HyperFrames ($0.00) and Veo 2 ($0.50), dynamically updating the donut savings meter. | Truly interactive calculation, but hardcoded to 2 sample shots. | Support importing any `ProductionScene` from `.studio/projects/`. |
| **Character 6-View Turnaround** | 6-angle turnaround rotator (Front, 3/4 L/R, Profile L/R, Back) | **LIVE / SIMULATED** | CSS 3D wireframe rotates dynamically on angle button click; displays realistic similarity (96.8%) and drift (0.01%) scores. | Renders a wireframe silhouette rather than actual binary character sprites. | Allow uploading or displaying real character PNG assets when available. |
| **Production Cost Donut Gauge** | Donut gauge with animated percentage and comparison boxes | **LIVE / DERIVED** | Re-computes live percentage when shot routes change via CSS variable `--percent`. | Derived from active shot card state. | Retain; add note distinguishing estimated vs verified cost. |
| **Deliverables Export Hub** | Download buttons for HTML5 player, OTIO, EDL, and Manifest | **LIVE** | Generates real downloadable files (`.html`, `.otio`, `.edl`, `.json`) on click via `Blob` and `URL.createObjectURL`. | Generates valid files, but based on sample data. | Retain; feed from actual pipeline export step outputs. |

---

## Key Action Items for Phase 16

1. Add prominent execution mode badge to header: `[MODE: LOCAL]`, `[MODE: MOCK]`, or `[MODE: PRODUCTION]`.
2. Do not display estimated savings as "actual money saved" without explicitly clarifying baseline assumptions.
3. Ensure the UI can load real project artifacts generated by `studio run` from `.studio/exports/` and `.studio/projects/`.
